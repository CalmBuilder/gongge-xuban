# 当前 SOP 编辑、反馈候选与原发布链

普通编辑继续使用现有 Skill API。反馈改进从已授权、来源可证明的 SOP 材料进入同一 DistillPage 和 SkillEditor，候选保存仅更新 `SkillEditCandidate`，不修改活动 Skill、员工分支或 Runtime 发布版本。普通 DTA 材料不能伪造 SOP 身份。

`/api/enterprise/skills/feedback-candidates` 的接口：

| 方法与相对路径 | 服务端合同 |
| --- | --- |
| `POST /` | 当前管理者提交材料 ID、目标员工与幂等键；服务端读取来源修订和实际发布基础，建立唯一当前编辑关联 |
| `GET /editor-context` | 返回当前关联 ID、修订、scope/profile 身份及明确重载后的普通编辑 nonce，不返回材料或候选正文 |
| `GET /{id}` | 当前权限与来源有效时读取隔离正文、原版和差异；失效来源拒绝，合法发布历史只返回安全回执 |
| `PUT /{id}` | 精确 `expected_revision` 保存隔离候选；原轮发布与当前基础不同必须明确保存差异确认 |
| `POST /{id}/reject` | 拒绝候选，保留活动版，旧关联不能经普通保存洗掉来源 |
| `POST /{id}/reset` | 明确丢弃并加载所选当前范围原版，签发新的普通编辑身份；旧候选、缓存、nonce 不能复活 |
| `POST /{id}/publish` | 人工确认精确候选修订、基础发布 ID/校验和与稳定幂等键，沿原编译、工具/参与者绑定、版本和指针链同事务发布 |

反馈改写沿原 `/{skill_id}/rewrite`、`/rewrite/stream` 和 `/rewrite/jobs`，请求携候选 ID 与精确修订。模型、工具、材料和当前正文由服务端冻结；同步与原后台任务使用真实 actor。准备事务提交后调用 SDK，每次模型发送、反思/修复/重试、结果落地和缓存读取重新校验授权、来源、基础和生成代数。取消先持久化生成屏障，迟到结果不可写回。错误使用稳定安全码，缓存失效清除旧正文。

缓存只允许同次生成已提交结算的单次修订递增窗口，发送和写回仍要求精确修订；人工编辑、取消和新生成都会推进代数。原进程内 job 重启丢失时明确失败，浏览器仅保存 job ID，不以浏览器草稿重建来源权威。

浏览器恢复的 GET job 初检和后续 stream 请求共用错误分类：稳定 `FEEDBACK_CANDIDATE_UNAVAILABLE` 清除候选正文、材料、草稿快照、差异、历史、弹窗、在途操作和 job 指针；通用 404 `Job not found` 只结束旧 job 并重新校验当前候选。候选仍有效则保留未保存编辑，权限/来源/基础明确失效才清私密状态。网络暂断、408/429 和候选短事务写冲突保留合法编辑；旧核验回包不得清除合法保存的新修订，失效后的缓冲事件不得恢复旧正文。合法已发布历史仍仅读最小安全回执。

`SkillVersion` 保留原表和不可变发布 ID，唯一身份为 tenant/skill/scope/version，整体 scope 为空串。员工分支历史 ID 与 Runtime 发布 ID 各司其职；管理响应公开实际 `publication_id`、scope 与 checksum，新实例绑定该精确发布，旧实例继续冻结原 ID/定义。MySQL 执行 Alembic `0091/0092/0093`；`0093` 为已发布版本编译校验值兼容迁移，保留旧发布身份并登记可验证的当前编译校验别名。SQLite 在桌面兼容初始化末尾执行同一兼容迁移。

本说明描述已实现接口。SD-7 F2/F3 的验收状态以[当前进度](../../../docs/StaffDeck能力蒸馏-7adc7c8/implementation/进度.md)为准；候选或发布成功不等于真实业务改进已经验收。
